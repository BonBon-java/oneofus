# Instructions for Codex

## Project

- Start each task by inspecting the repository structure and existing conventions.
- Treat the existing codebase and its documentation as the source of truth.

## Working with code

- Follow the established language, framework, style, and architecture.
- Make the smallest change that solves the task; do not refactor unrelated code.
- Before adding a dependency, ask for confirmation.
- Do not change secrets, `.env` files, credentials, or production configuration without explicit permission.

## Validation

- After making changes, run the project's relevant formatting, linting, test, and build checks when available.
- If a check cannot be run, state why clearly.

## GitHub workflow

- Creating a pull request for a completed, reviewed change does not require an additional confirmation.
- Merge a pull request normally once all required protected checks are green and the change is safe; do not request a separate merge confirmation.

## Result

- Briefly list the files changed and what was done.
- Report the checks that passed or could not be run.
